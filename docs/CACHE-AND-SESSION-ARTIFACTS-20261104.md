# 运行目录与本局日志（2026-11-04）

本轮修复针对 OptiScaler 隔离运行目录持续膨胀，以及旧 ReShade / FSR 日志混入新会话。

## 原因与修复

`NrRuntimeLibrary.PrepareOpti` 原先递归遍历整个构建目录。DLL 使用硬链接，其他文件复制，所以崩溃转储、NR 追踪、截图、配置恢复历史也被复制进各游戏运行目录。第二次递归绑定 NR 还会遍历备份目录。

现在两个阶段共用 `OptiScalerRuntimePayload.Collect` 验证后的载荷：排除转储、日志、追踪、备份、截图、临时文件及共享运行状态。不进入排除目录；有效载荷中的重解析点拒绝部署。保留组件、插件、模型数据、许可和配置，DLL 仍使用现有链接机制，配置仍为各游戏独立副本。同步不主动删除历史证据或重置用户配置。

## 会话时间边界

所有日志统一要求 `LastWriteTimeUtc > 进程启动时间` 且不晚于采集时刻，检查覆盖 ReShade、FSR、OptiScaler 与启动器日志。手动导出也尽量使用实际进程启动时间。未产生本局文件时清单标记缺失，摘要只读取本局已提交的快照，不再回读旧原文。配置快照不要求本局修改过。

复制前先检查路径，实际打开后再次按文件句柄检查修改时间。按打开时长度读取，最大保留末尾 16 MiB，并跳过被截断的半行；临时文件提交失败不留下半份快照。快照通过同一把锁串行，避免定时与退出采集并发写目标文件。

## 转储归档

在本局快照时检查 OptiScaler 加载目录、配置日志所在目录的顶层 `OptiScaler_crash*.dmp`，以及当前游戏 Streamline 事件目录。只接收本局修改的非空转储，不扫描历史备份。文件仍被写入时保留源，后续快照重试。

归档目标为 `log/sessions/<本局>/opti-dumps/`。同卷移动保持文件身份，不再另存第二份大文件；跨卷先复制临时文件并核验 SHA256，提交后移除源。目标已有文件时保留双方，禁止覆盖。沿用每会话最多收集四份转储的上限，超出的源文件保留，不自动删除历史转储。第三方 DLL 的原始写入位置没有修改，集中归档在启动器采集时发生。

## 核验与交付

本轮记录位于 `artifacts/cache-space-audit-20261104/`。包含去重文件身份的占用快照、源码快照、编译日志、回归结果与本地部署核验。文件长度去重统计不等同于 NTFS 压缩/稀疏后的实际分配大小。

继续使用 1.4.8，本轮仅本地部署供用户验收；未启动启动器或游戏，不自动替换 GitHub 发行包。已有大型转储、追踪和备份没有批量删除或移动。
