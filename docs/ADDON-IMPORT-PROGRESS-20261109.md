# 单个 addon 本地安装进度修复（2026-11-09）

## 已确认的问题

- `InstallCoreAsync` 只给 addon 分支上报了识别阶段的 0%，没有把 progress 传给 `InstallAddonAsync`。文件复制期间界面没有可消费的进度。
- 装好任何本地文件后，无条件执行 `NrRuntimeLibrary.Consolidate`，遍历 Addons、所有 Opt 构建和整个缓存中的 NR 文件，重新计算内容哈希并整理硬链接。单个 addon 的安装只能写入 `.addon32` / `.addon64`，不应触发这项全库工作。
- 这两项代码事实可以解释进度不动以及无关的安装尾部开销；没有把未经计时的用户等待全部归因于 NR。

## 修改

- 识别以及无法量化的收尾操作使用不定进度；addon 安装显式接收进度对象。
- addon ZIP 复用支持取消和字节进度的统一解压器，映射到 2–30%；复制阶段按实际写入字节映射到 30–79%，回调限频约 100ms。
- 所有插件成功提交后到 80%，安装器成功返回前到 90%；页面继续负责列表刷新到 92%，刷新成功后才到 100%。
- 使用同目录唯一暂存文件，写入并关闭后再 Move 替换目标，保留旧硬链接归档的 inode；取消和写入/替换失败时删除本次暂存文件。
- 仅 addon 安装跳过全库 NR 整理。Opt、模块及覆盖包现有 NR 整理保留，未降低内容校验或硬链接要求。
- 页面按包类型显示刷新提示，并增加 `installMs`、`totalMs` 日志。已有 UI dispatch 和过期回调保护保留。

## 验证

- 用独占打开的无关 NR 文件验证 addon 安装无需读取它，且不会创建 NR 内容缓存。
- 原有覆盖包解压/复制进度、取消、路径安全、多个游戏包和锁定文件回归继续通过。符号链接夹具因当前进程缺少创建权限按原有规则跳过。
- 首次测试对 Windows 占用目标只捕获 IOException，实际系统返回 UnauthorizedAccessException；已修正测试的预期异常集合后重跑通过。
