# F6 Launcher 页面交互后续修复

用户自行实测 1.4.8 后反馈：全局插件仍显示“正在读取插件目录”的阻断提示，游戏模块页进入也会卡顿。不能把此前编译通过或后台线程改造当作实际交互已经验收。

## 模块页

- 原 OnNavigatedTo 在 UI 线程完成旧配置迁移、JSON 读取、DLL 解析、版本目录扫描，改为可取消的后台快照；离页及新游戏请求会丢弃过期结果，扫描期间不禁止导航或编辑已有卡片。
- 原每张卡片调用 IsUsed，默认选择未保存时每次都会重新调用 ModuleRegistry.List；现在单遍扫描后统一推导默认选择，勾选沿用该快照，并保留用户显式保存但当前缺失的模块 key。
- ModuleRegistry 的五处 OptiScalerLibrary.List 仅需版本与 DLL 路径，却默认递归统计目录大小，全部关闭该统计；磁盘实际身份和版本要求保持不变。
- 只有桥模块解析桥配置路径；不为所有模块重复做一次 DLL 解析。桥配置控件及 INI 读取延至展开，桥版本解析移至后台。
- 加载时保留现有选择，刷新中发生编辑则重新读取最新设置；失效导航、过期版本回调与 ComboBox 重建产生的空选择不回写配置。
- 新增 Modules page 的后台读取与 UI 应用耗时日志，便于用户实测后定位。

## 全局插件页

- 被动目录读取不再占用安装锁；改成底部行内状态，导航和已经显示的卡片保持可用。
- 随包目录、账本、诊断、模块注册和文件状态读取放到后台，先显示目录/上次缓存，再补充真实磁盘状态；隐藏的 OptiScaler、模块标签按需加载。
- 卡片逐张增量发布，保留完整业务快照；安装器查找 DLL 的来源目录独立读取完整 Opt 库，不从尚未显示完整或已搜索过滤的可见列表取值。
- 依赖刷新结果的安装、删除、本地包导入和版本切换均等待真实后台刷新完成，再回填新卡片；写操作会取消旧的被动读取，避免旧结果覆盖安装后的数据。
