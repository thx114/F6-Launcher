# FPS 解锁生命周期候选（2026-11-06）

版本保持 `1.4.8.1`。本轮只制作独立候选，不修改测试安装，不启动游戏，不上传 GitHub。写者负责 `FpsUnlocker` 和远程资源退休；协调者负责 CLI 会话、集成与候选构建；独立复核者只读审查两部分及其边界。

## 改变的行为

CLI 在发起解锁前登记会话，以 PID 和进程启动时间区分实例。`launch_game` 等待明确的附加结果；附加失败返回失败原因，不因此关闭已启动的游戏。附加成功后继续执行批次中的等待、采集或显式停止动作，全部步骤完成后仍保留宿主，直到对应游戏进程退出。调用者取消不再提前销毁已建立的目标槽位。

附加流程在首次异步等待前固定原始进程句柄，新增远程句柄通过 `CompareObjectHandles` 核验为同一内核对象，核验失败时拒绝远程读写及注入。错身份回归确认 Read/Allocate/Write/Start 均未调用。

会话的附加结果与终身完成分开。等待期间新增的会话也必须完成；某个监护任务异常不会使后来登记的会话失去宿主。正常 CLI 收尾最后等待远程资源退休队列。Ctrl+C 在附加或资源退休尚未结束时保持宿主；控制台输出管道关闭不会绕过这套等待。

`FpsUnlocker` 采用单次附加的真实资源所有者。保留原始进程与远程线程句柄，检查完整读写和指令缓存刷新，处理部分初始化失败；本地附加及维护循环完成前不释放其资源。`SetTarget` 与 `Dispose` 通过同一把锁协调。

已经启动过远程线程时，即使线程句柄已 signaled，也保留远端代码、本地目标槽位及句柄，直到原始进程句柄确认退出。无法确认退出、等待失败、释放失败时保留所有者重试。现有 shellcode 没有可验证的全局停用协议，故不通过清零 PID 或强停远程线程释放资源。进程退出后的远端地址空间由系统回收。

## 使用限制

启动壳会等待 CLI 子进程，调用方应允许它保持到游戏退出；外部脚本强杀、关闭控制台及系统终止不能当作安全停用。当前候选修复 CLI 的正常收尾及进程存活期间的资源退休，不提供 shellcode 卸钩协议，也不保证 GUI 完全退出后仍维持本进程槽位。使用此 CLI 候选验证时，应保持其宿主存活到目标退出。
