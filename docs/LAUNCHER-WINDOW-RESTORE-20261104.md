# 窗口恢复卡顿调查与修改

- 未找到主程序调用 `EmptyWorkingSet` / `SetProcessWorkingSetSize` 的实现。原来的 App 60 秒 GC timer 没有被启动；不能把它误报为每分钟实际执行的 GC。
- 已确认 `MainWindow.Hide()` 在 UI 线程调用无参数 `GC.Collect()`；激活窗口的原生消息处理器内同步发送刷新通知，接收者可能查文件、检查游戏版本或恢复背景。这些是源码可见的阻塞风险，现有日志不能证明其占用秒数。

## 修改

- 删除隐藏窗口时的显式完整 GC，以及从未启动的 App GC timer。由 .NET 运行时自行安排主进程 GC，RPC 独立进程不在本次窗口恢复修改范围内。
- 保留及时更新标题栏拖拽区域，把激活刷新排到低优先级 dispatcher 回调；合并紧邻的激活消息，窗口已关闭时丢弃回调。保留原来的超过十分钟/跨整点刷新判断。
- 添加低频 `Window activation:` 记录，区分 dispatcher 排队、同步订阅者和后续队列耗时，同时记录工作集、私有内存和 Gen2 次数。记录只覆盖消息已进入应用后的区间，不代表首次输入到画面出现的完整延迟，也不构成硬页错误测量。

原始修改前源码和日志审计摘要在 `artifacts/perf-windowrestore-20261104/`。未进行运行时性能测量，不能宣称秒数改善或已解决外部工具清理后的所有卡顿。
