# 覆盖包首次 INI 初始化与单入口发行包（2026-11-04）

## 报错与证据边界

用户截图显示旧 4.2 覆盖包已完成文件导入和首个插件禁用步骤，随后 `set_ini_keys` 报“找不到目标 ini”。旧实现既用于游戏 `ReShade.ini`，也用于 `file` 显式指定的其他 INI，却统一提示先启动游戏生成 ReShade.ini。截图没有实际目标路径，截图中的 E 盘也不在本机，不能据此确认究竟缺失哪个文件。

此前提到的 `HoYoShade.UserNR.ini` 来自旧打包脚本，是那个包显式请求写入的参数保存文件，不是启动器所有安装都必须具备的文件。本次不按这个文件名做特殊处理。

## 修复

- 游戏 ReShade.ini 不存在时，导入动作执行前先准备目标。优先保留宿主模板原始字节；宿主本身有效但模板尚未生成时，直接按当前宿主的绝对滤镜、贴图和插件路径生成游戏配置，无需先运行游戏。
- 游戏已有 INI 时不替换整份文件，仅执行覆盖包声明的键写入/移除，保留其他参数、NR 设置和注释。
- `set_ini_keys`、`set_ini`、`write_ini` 共用 `PackIniAction`。包显式请求写入但尚不存在的其他 `.ini` 文件也可按请求创建；没有相关步骤时不创建额外参数文件。
- 显式动作使用严格写入接口，文件被占用或写入失败不会伪装成“值相同”，也不会被记为 once 成功。错误带完整目标路径和异常原因。
- 历史缺失文件错误可能已记为 pending。交互执行时可单独确认重试当前 INI 步骤，保持其余成功记录和原 plan 不变；后台启动不自动重试 pending，非 INI 步骤不开放此恢复入口。

## 包根入口

新普通包及 Full 脚本只生成根目录 `F6Launcher.exe`。主程序和 RPC 共用 Core 的便携入口定位器，优先识别 F6，兼容已有安装中的旧文件名。协议注册和更新重启指向当前入口。发行校验拒绝根目录旧 `HoYoShadeHub.exe`；从旧 Full 派生普通更新包时也过滤该旧入口。原始 LICENSE、Starward_LICENSE、NOTICE.md 继续置于包根和应用目录。

## 验证与部署

版本沿用 1.4.8。构建输入快照、编译日志、回归日志、普通包逐文件清单及本地部署记录保存在 `artifacts/pack-ini-fix-20261104/`。

隔离目录验证：INI 动作 42 项、目标准备 30 项、once/导航 169 项、F6 单入口识别 7 项，共 248 项通过。包含缺少主 INI、宿主没有模板、显式命名 INI、用户 NR 参数保持、占用失败以及历史 pending 恢复后已成功步骤不重复执行。

本次不启动或强退启动器/游戏，不把构建或隔离检查描述为真实 UI/游戏验收。测试安装仅增加版本化程序目录并切换 version.ini；根启动壳、用户配置及已有硬链接按部署清单核验，已运行进程需用户自行重启后使用新构建。GitHub 是否替换以实际上传记录为准。
