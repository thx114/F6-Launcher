## 静态确认的无反馈分支及修复

- `MainView` 原先仅识别 `File.Exists` 为真的输入；零个覆盖包时可能静默返回。识别损坏 ZIP 的异常会让整批路由退出，只在 Shell 分发层写错误。
- 全局插件页原先对目录/不存在路径直接返回，且不写拒绝原因；只显示“收到文件/正在安装”，没有真正安装，用户可能感知为无反应。
- 新增只读 `LocalPackageDropInput`：明确拒绝目录、缺失文件、无扩展名及未支持格式，并逐项收集压缩包读取失败；不把任意目录安装为覆盖包，不修改用户输入。
- 窗口级路由补充逐项路径类型、扩展名、识别结果和页面分发日志。识别失败不再阻断同批有效覆盖包；页面忙、导航失败、等待超时和切页中断均给出可见提示。
- 全局插件页使用相同输入验证，拒绝时同时更新状态、InfoBar 和窗口 toast；安装开始与文件安装完成记录路径、包类型及目标。文件已安装和后续覆盖包动作完成仍是不同阶段。
- 非覆盖包仍交给原页面处理，保留 Mod 页面拖入目录的现有行为；本次不增加解压后目录导入。
